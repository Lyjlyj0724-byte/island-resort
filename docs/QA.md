# 发布前检查清单（QA）

[← 回到 README](../README.md)

这份清单面向**人工检查**：自动化测试覆盖了昼夜循环与文案/素材一致性，但 3D 画面、触摸手势、声音解锁和部署结果仍需要在浏览器里实际点一遍。

建议在干净环境（重新 `npm ci`）里检查一次，再用生产构建（`npm run preview`）检查一次。

## 0. 环境与自动检查

- [ ] Node.js 版本满足 `package.json` 的 `engines`（Node.js **22.12+**），可用 `node -v` 确认；项目根目录的 `.nvmrc` 是 `22.12.0`
- [ ] 仓库包含 `package-lock.json`（`npm ci`、CI 和 Vercel 都依赖它）
- [ ] `npm ci` 成功，没有依赖冲突
- [ ] `npm test` 通过：`tests/dayCycle.test.ts`（昼夜循环、光照、时间推进、自动/手动模式）与 `tests/site.test.ts`（文案与素材一致性）
- [ ] `npm run build` 成功（先 `tsc -b` 再 `vite build`），`dist/` 正常生成
- [ ] `npm run check` 通过：测试 + 构建（测试中包含文案/素材一致性与本机路径检查）
- [ ] `npm run preview` 能启动，默认地址 `http://localhost:4173`
- [ ] `npm run format` 之后没有大批无关改动（可选；CI 不检查格式）

### CI 说明

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 在 push 和所有 Pull Request 时运行：

1. `actions/checkout`
2. `actions/setup-node`（Node 22 + npm 缓存）
3. `npm ci`
4. `npm test`
5. `npm run build`

CI 只做测试与构建，不跑浏览器 E2E，也**不跑** `format:check`（避免格式偏好阻断构建）。
